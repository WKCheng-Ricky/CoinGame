# Coin Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a static, dependency-free browser game where the player matches a target amount by tapping UK coins, in Endless and Custom modes.

**Architecture:** Pure logic (`coins.js`, `game.js`) is separated from DOM code (`render.js`, `main.js`). All money is integer pence. State is one plain object; every action updates it and calls `render(state)`. Coins are inline SVG built from data.

**Tech Stack:** HTML, CSS, vanilla JS (ES modules). Node built-in test runner (`node --test`) for unit tests. No runtime or dev dependencies.

**Spec:** `docs/superpowers/specs/2026-10-27-coin-game-design.md`

## Global Constraints

- No backend, no build step, no runtime dependencies, no dev dependencies.
- UK coins only: 1p, 2p, 5p, 10p, 20p, 50p, £1, £2. Coin set lives in data (`coins.js`).
- All amounts are integer pence. Pounds are produced only for display.
- Random targets: integers 1 to 999 pence. Custom amounts: 1 to 9999 pence (£99.99), cap is one constant.
- Pile is grouped by denomination: a map from coin id to count, shown as stacks with a count badge (e.g. "20p ×3"). Tapping a stack removes one coin; tapping a tray coin adds one. No maximum pile size.
- Running total is always visible. Check on an empty pile reports "under".
- Over/under hints: "A bit too much" / "Not enough yet". No penalty; the pile stays.
- Tap targets at least 44px; `touch-action: manipulation` on buttons; coins and stacks are `<button>` elements labelled like "Add 20p"; total and result message use `aria-live`.
- Only `render.js` and `main.js` touch the DOM. `game.js` and `coins.js` import cleanly in Node.
- No persistence. Back mid-round discards the round without confirmation; the Endless rounds counter resets when Endless is started again.

## Review Focus

1. Amount text a person might type: `" 3.95 "`, `"£.5"`, `"3."` are accepted; `"1,50"`, `"1e2"`, `"£"`, `""`, `"3.955"` are rejected with a message (Task 2).
2. Cap boundaries: `"99.99"` accepted, `"100"` rejected, `"0.00"` and `"0"` rejected (Task 2).
3. Very large piles: 9999 × 1p totals correctly and removing from an empty stack never produces negative counts (Task 1).
4. Endless target never repeats the previous value, including at the range edges 1 and 999 (Task 2).
5. A solved round cannot be re-submitted or altered by further taps; Play again/Next start with an empty pile (Tasks 5 and 6, manual checklist).

### Task 2: Amount parsing and random targets

**Files:**
- Modify: `src/game.js`, `tests/game.test.js`

**Interfaces:**
- Consumes: nothing new.
- Produces (`src/game.js`):
  `MAX_RANDOM_PENCE = 999`, `MAX_CUSTOM_PENCE = 9999` (exported constants);
  `parseAmount(text: string): { ok: true, pence: number } | { ok: false, error: string }`;
  `randomTarget(previous?: number, rng?: () => number): number`.

- [ ] **Step 1: Write failing tests.**
  - `parseAmount` accepts (→ pence): `"3.95"→395`, `"£3.95"→395`, `"4"→400`, `".5"→50`, `"£.5"→50`, `" 3.95 "→395`, `"3."→300`, `"3.9"→390`, `"0.01"→1`, `"99.99"→9999`.
  - `parseAmount` rejects (`ok === false`, non-empty `error`): `""`, `"£"`, `"abc"`, `"-1"`, `"£-1"`, `"0"`, `"0.00"`, `"3.955"`, `"1,50"`, `"1e2"`, `"100"`, `"99.995"`.
  - `randomTarget(undefined, () => 0) === 1`; `randomTarget(undefined, () => 0.999999) === 999`.
  - `randomTarget(1, () => 0) !== 1`; `randomTarget(999, () => 0.999999) !== 999`.
  - 2000 calls of `randomTarget(500)` with real `Math.random`: each is an integer in 1..999 and never 500.

- [ ] **Step 2: Run `npm test`.** Expected: new tests FAIL.

- [ ] **Step 3: Implement `parseAmount`.** Trim; strip at most one leading `£`; require the remainder to match digits-optional, optional `.` followed by 0 to 2 digits, with at least one digit overall; convert to pence with integer arithmetic (no `parseFloat` multiplication); reject 0 and anything above `MAX_CUSTOM_PENCE`. Error text is your choice but must distinguish "not a valid amount" from "too large" and "must be more than zero".

- [ ] **Step 4: Implement `randomTarget`.** Draw from the 998 non-`previous` values so the result stays uniform and deterministic: `n = 1 + floor(rng() * 998)`, then `if (previous >= 1 && previous <= 999 && n >= previous) n++`. When `previous` is undefined or out of range, use `1 + floor(rng() * 999)`.

- [ ] **Step 5: Run `npm test`.** Expected: all pass.

- [ ] **Step 6: Commit** with message `Add amount parsing and random target generation`.
